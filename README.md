# Бозшаколь: цифровой двойник медного карьера на OpenEgiz

Двойник карьера Бозшаколь (KAZ Minerals Bozshakol, Павлодарская область) и пути руды от забоя
до двух обогатительных фабрик — сульфидной и фабрики глинистой руды. Пользователь — горный
диспетчер смены. Описание замысла, модулей и данных — в [SUBMISSION.md](SUBMISSION.md).

## Запуск с нуля

Проверено на Ubuntu 24.04 с Docker 29 и Docker Compose 2.40 (нужно 6 ГБ памяти для Docker).
Все команды выполняются из корня репозитория.

```bash
sudo apt-get update && sudo apt-get install -y make
```

```bash
make bozshakol-pull
```

Скачивает образы платформы и рудника и собирает их заранее: на чистой машине — до ≈ 25 минут
(зависит от сети), повторно — несколько секунд. Так платформа потом поднимается не под нагрузкой загрузки.

```bash
make bozshakol
```

Эта команда поднимает платформу OpenEgiz (при первом запуске создаёт пароли в `deploy/compose/.env`),
собирает образы рудника, создаёт двойники и запускает сервисы, 3D-сцену и дашборды: после `make bozshakol-pull` —
около 5 минут; без него на чистой машине вместе со скачиванием — до ≈ 35 минут; повторный запуск — 2–3 минуты.
Если начальная настройка платформы (init) оборвалась, потому что Ditto ещё не успел ответить, команда сама повторяет
подъём один раз через 30 секунд. Если запуск всё равно оборвался — повторите `make bozshakol`. В конце команда печатает адреса.

Проверка работающего стенда (двойники, телеметрия, сценарии, 3D-страница, история в InfluxDB, Grafana; в конце — перезапуск сервисов переработки и транспорта с проверкой, что бункер, склады и счётчики восстановились):

```bash
make bozshakol-check
```

Остановить (данные остаются) и снова поднять:

```bash
make down
```

```bash
make up
```

## Что открыть в браузере

| Что | Адрес | Вход |
|---|---|---|
| 3D-сцена карьера (панель диспетчера, сценарии «что если», карточки двойников) | http://localhost:8095 | не нужен |
| Grafana → Dashboards → папка **Бозшаколь** (обзор, транспорт, геология, переработка и энергия) | http://localhost:3000 | `admin` / значение `GRAFANA_ADMIN_PASSWORD` из `deploy/compose/.env` (показать: `grep GRAFANA_ADMIN_PASSWORD deploy/compose/.env`) |
| Grafana → приложение **OpenEgiz** → **Twins** — иерархия двойников `kz.bozshakol`; **Types** — типы двойников `kz.bozshakol.types:<вид>` | там же | там же |
| Ditto API: все двойники | http://localhost:8080/api/2/search/things?namespaces=kz.bozshakol | `ditto` / `DITTO_PASSWORD` из `deploy/compose/.env` |

В Grafana рядом с папкой «Бозшаколь» может быть пустая папка шаблона платформы «OpenEgiz Examples» (её создаёт первый
запуск платформы для примеров; рудник в ней ничего не хранит).

Порты задаются в `deploy/compose/.env` (`GRAFANA_PORT`, `DITTO_PORT`, `BOZSHAKOL_WEB_PORT` и другие);
в таблице — значения по умолчанию.

### 3D-сцена

На странице http://localhost:8095 — **схема рудника** на степи до горизонта: расстояния сжаты в 2 раза, здания и склады
показаны крупнее для наглядности (в 1,6–1,8 раза; каждое растёт от своего подъезда или торца и не наезжает на дороги,
конвейер и стоянку), отвал и хвостохранилище — в реальном размере (отвал Ø 800 м); карьер ≈ 4,4 × 1,1 км, 13 уступов по 15 м с бермами и съездами, глубина — с вертикальным
масштабом ×1,5; подвижная техника — ×1,25 к реальному размеру (экскаватор крупнее самосвала); на дальнем плане над
машиной — цветной значок-стрелка (цвет груза или состояния), вблизи — модель. Вся земля — одна функция высоты:
степь, бермы и стенки уступов, съезды, площадки и дороги; дороги — ленты по этой поверхности, техника ставится на неё
и наклоняется по уклону, буровые станки ставятся на ровное место бермы. Съезды в схеме — непрерывные спирали вдоль
борта (уклон ≈ 10 % на схеме, ≈ 6–7 % на местности) с ровными площадками у развилки к забою на уступе; дробилка врезана
в землю — самосвал разгружается задом в бункер, лента выходит из портала подземной галереи; самосвал в карьере не
стоит на откосе — сцена ставит его на ближайшую дорогу; у съезда борт — ровный откос, уступы проступают из него плавно, вдоль своих кромок (без ступенек и зубцов). Едущие самосвалы держатся своей полосы, очереди к экскаватору,
дробилке, складу глины и стоянка у заправки выстраиваются вдоль подъезда, место в очереди закреплено за машиной,
сдвиги сглаживаются (это только картинка — данные двойников не меняются). Двойной клик по объекту — облёт
(Esc — выход); колесо мыши, тачпад и R/F — плавное приближение (≈ 11 % расстояния за щелчок). Места узлов и объектов —
`bozshakol/core/diorama.json`, перенос реальных координат двойников в схему — `bozshakol/web/diorama.js`. Самосвалы
и экскаваторы движутся по данным двойников (шапка груза — по цвету руды: сульфидная зелёная, глинистая рыжая, вскрыша
серая; авария — красно-пурпурный корпус и значок «⛔ авария» с пульсом, резерв — серо-белый).

Реальная местность — кнопка **«Фото местности»**: окно со спутниковым снимком Sentinel-2 (29.06.2024, 10 м/пиксель,
квадрат 6 × 6 км) с подписями «карьер», «дробилка», «фабрики», «отвал», «хвостохранилище» и полной атрибуцией
Copernicus; закрывается крестиком или Esc, сцена от него не зависит. Источники и лицензии — в
[bozshakol/data/terrain/README.md](bozshakol/data/terrain/README.md).

- Кнопки-виды сверху: «Весь рудник», «Карьер», «Дробилка и конвейер», «Фабрики», «Сверху (карта)» —
  вид сверху ортографической камерой как 2D-карта карьера; «Следовать» — камера идёт за выбранным самосвалом.
- Клик по технике или объекту — карточка с живыми признаками двойника. Подписи крупных объектов видны
  всегда, подписи техники — при приближении, наведении или выборе.
- Слева — панель диспетчера. Наверху крупно четыре главные цифры смены: руда на фабрики (факт и план, т/ч), медь
  в питании, ожидание у экскаватора, режим диспетчера; под ними — **совет диспетчеру** (двойник `advisor`, сервис
  `bz-advisor`): главный крупно (причина и ожидаемый эффект — под «Почему и что даст»), остальные одной строкой, цвет
  по приоритету; значок «совет» над объектом в сцене, клик по совету ведёт камеру к нему; появление и снятие совета —
  в журнале событий. Правила — в договоре, раздел 11. Остальное — в свёрнутых разделах (щелчок по заголовку):
  сценарии «что если» с кнопками «Включить / Выключить» (этот раздел открыт сразу), фабрики (план/факт за смену), транспорт (самосвалы в работе /
  в очереди / в аварии, очереди, погода), журнал событий модели, легенда, настройки. У каждого блока «?» — пояснение
  простыми словами. Кнопка в заголовке панели сворачивает её в узкую полоску (на ней ⚠, если есть совет);
  положение запоминается в браузере.
- Включённый сценарий показан плашкой «Активные сценарии» сверху и значком на затронутом объекте.
  В истории (InfluxDB, Grafana) сценарии видны по признакам `mine.scenario_<имя>` (1/0) и
  `mine.active_scenarios`; на обзорном дашборде — полоса «Активные сценарии».
- Самосвал, который стоит, потому что до его цели нет пути по открытым дорогам (закрыт съезд), подписан
  «ждёт: съезд закрыт»; отвал подписан «Отвал вскрыши (пустая порода)».
- Свет и цвет: тональное отображение AgX, под каждой машиной мягкая тень-пятно (техника стоит на земле и без теней
  «Обычного» качества); тревога — красно-пурпурная (#d1236a), а не красная, и не только цветом: значок ⚠ у плохой
  цифры, пульс у «авария» и критичных советов (выключается при «меньше движения» в системе); маячки техники: работает —
  бирюзовый, внимание — янтарный, тревога — пурпурно-красный (различимы и при дальтонизме).
- Синий круг к западу от фабрики — хвостохранилище (пруд для отходов обогащения), подписан и с общего вида.
- Живой фон: куртины кустов и ковыль в степи, пятна суглинка и полыни, ЛЭП от подстанции к фабрикам и дробилке,
  ж/д ветка с хопперами у склада концентрата (концентрат с Бозшаколя вывозят по железной дороге — `data/SOURCES.md`),
  служебные машины (поливомоечная, грейдер, пикап мастера) на своих путях вне карьерных дорог, лёгкая пыль за
  гружёными самосвалами, облака и их тени на степи (в качестве «Обычное», без видеокарты, не рисуются пучки ковыля, шпалы и тени
  облаков, кустов — 120 куртин-кустов из 300; в «Высоком» — всё). Заправка крупнее не помещалась на прежнем месте (там полотно дороги к отвалу) — стоит рядом, у стоянки.
- Кнопка **«Фото местности»** сверху — спутниковый снимок реального Бозшаколя с подписями объектов.
- **Освещение** (панель → «Настройки»): «День» или «Ночная смена» — тёмное небо, огни мачт освещения карьера, фары самосвалов,
  светящиеся окна корпусов.
- **Качество** (панель → «Настройки»): «Высокое» — тени от солнца, ореолы огней, пыль за самосвалами; «Обычное» — быстрее; при первом запуске
  сцена 3 секунды меряет скорость кадров и сама выбирает «Обычное», если кадров меньше 25 в секунду.
- Кнопка **«Как посмотреть»** в правом нижнем углу открывает путеводитель (он же появляется при первом открытии).
- У каждого сценария в панели — строка «что смотреть» и кнопка **«показать»**: камера летит к главному объекту.
- Карьер — уступы с породой, бермами и съездами; вокруг — хвостохранилище, ЛЭП,
  ограждение и мачты освещения (положение части объектов — допущение, см. `bozshakol/data/SOURCES.md`).
- Управление с клавиатуры: **W/A/S/D** и стрелки — движение (вперёд — куда смотрит камера), **Пробел / Shift** —
  вверх / вниз (выше — быстрее), **Q/E** — поворот, **R/F** и колесо мыши — дальше / ближе; **1–5** — виды,
  **Home** или кнопка **«Наверх»** — плавно к общему виду, **G** — следовать за выбранным самосвалом / отпустить,
  **Esc** — снять выбор, **?** — подсказка. Мышью можно смотреть и вниз, и в небо; камера не опускается ниже земли,
  стен и потолка нет — из карьера можно вылететь в любую сторону.

Сценарии «что если» включаются кнопками в 3D-сцене или записью одного признака, например:

```bash
. deploy/compose/.env && curl -u "ditto:$DITTO_PASSWORD" -X PUT -H 'Content-Type: application/json' -d true "http://localhost:$DITTO_PORT/api/2/things/kz.bozshakol:scenarios/features/crusher_stop/properties/value"
```

Отмена — то же самое с `false`. Полный список сценариев — в [bozshakol/contract/README.md](bozshakol/contract/README.md).

## Как проверить за 5 минут

1. Запустите стенд: `make bozshakol-pull`, затем `make bozshakol` (на чистой машине всего до ≈ 35 минут, повторно 2–3 минуты) и откройте http://localhost:8095.
2. Прочитайте путеводитель «Как посмотреть двойник» (откроется сам) и нажмите «Понятно».
3. Осмотритесь: виды 1–5 («Весь рудник», «Карьер», «Дробилка и конвейер», «Фабрики», «Сверху»), мышь или W/A/S/D.
   Сцена — схема рудника; реальная местность на спутниковом снимке — кнопка «Фото местности».
4. Кликните самосвал: справа — карточка с живыми данными его двойника (груз, скорость, топливо, пункт назначения),
   голубая линия — его маршрут до цели; «Следовать за самосвалом» — камера пойдёт за ним.
5. В панели слева в разделе «Сценарии «что если»» включите «Остановка дробилки» и нажмите «показать»: у дробилки — красный маячок и подпись
   «стоит · не принимает»; гружёные самосвалы ждут у дробилки — очередь растёт (на стенде — до ≈ 10 машин за
   4 минуты; если в момент включения к дробилке никто не ехал, очередь набирается не сразу); склад перед фабрикой
   тает, в подписи склада — прогноз «фабрика встанет в …», в панели — совет диспетчеру с цифрами (перевести
   гружёные на вскрышу или в резерв). Выключите сценарий — дробилка снова принимает руду, очередь рассасывается,
   совет снимается.
6. Откройте «Дашборды Grafana» (ссылка в панели) → «Бозшаколь — обзор»: подача на фабрики, полоса активных
   сценариев и советы во времени.
7. Кнопка **«Сверка с реальностью»** сверху: таблица «модель / реальность / отклонение» — подача на обе фабрики, содержание
   меди, извлечение, темп меди в концентрате, ожидание у экскаватора, удельная электроэнергия; зелёный — в пределах ±10 %,
   жёлтый — больше; источник каждой реальной цифры — в подсказке строки. Подача на фабрики совпадает по построению
   (план модели взят из того же отчёта) — это калибровка, а не независимая проверка. История — Grafana → «Бозшаколь — сверка с реальностью».
8. Проверка стенда одной командой: `make bozshakol-check`.

Первые 20 модельных минут после старта (≈ 2 минуты реального времени) советник пишет «рудник разгоняется»: оценка
привоза руды за час появляется, когда накопится час данных; в сверке с реальностью первый час — пометка «модель разгоняется».
Величина, которую модули не публикуют, в сверке показана как «нет данных»; сейчас публикуются все семь.

## Как устроен репозиторий

| Путь | Содержимое |
|---|---|
| `bozshakol/` | Всё наше. `contract/README.md` — договор команды: имена и иерархия двойников, протокол телеметрии, счётчики, сценарии, владельцы папок |
| `bozshakol/core/` | Координатор: создание двойников (`bz-setup`), модельное время, погода, итоговые показатели (`bz-core`), `geometry.json`, общая библиотека `bzlib/` |
| `bozshakol/modules/haulage/`, `geology/`, `processing/` | Модули: транспорт и диспетчеризация, геология и качество руды, переработка и энергия — по сервису, `twins.json` и README на модуль |
| `bozshakol/web/` | 3D-сцена (three.js локально, nginx), слои модулей в `web/layers/` |
| `bozshakol/grafana/` | Дашборды Grafana |
| `bozshakol/data/SOURCES.md` | Источники цифр и допущения |
| `bozshakol/data/terrain/` | Рельеф Copernicus DEM и снимок Sentinel-2 вокруг карьера (готовые файлы + скрипт воспроизведения, лицензии) |
| `bozshakol/check.sh` | Проверка работающего стенда |
| `SUBMISSION.md` | Описание решения |
| `examples/mine/` | Пример рудника из шаблона платформы; в решении не используется |
| `OPENEGIZ.md`, `OPENEGIZ.ru.md` | Документация платформы OpenEgiz v1.0.4: требования, Windows/WSL2, устранение неполадок |

Справка о платформе (установка Docker, Windows/WSL2, `make up`, `make smoke`, `make clean`) —
в [OPENEGIZ.ru.md](OPENEGIZ.ru.md) / [OPENEGIZ.md](OPENEGIZ.md).
