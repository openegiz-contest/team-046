# Бозшаколь: цифровой двойник медного карьера на OpenEgiz

Двойник карьера Бозшаколь (KAZ Minerals Bozshakol, Павлодарская область) и пути руды от забоя
до двух обогатительных фабрик — сульфидной и фабрики глинистой руды. Пользователь — горный
диспетчер смены. Описание замысла, модулей и данных — в [SUBMISSION.md](SUBMISSION.md).

## Запуск с нуля

Проверено на Ubuntu 24.04 с Docker 29 и Docker Compose 2.40 (нужно 6 ГБ памяти для Docker).
Все команды выполняются из корня репозитория.

```bash
sudo apt-get update && sudo apt-get install -y make
```

```bash
make bozshakol
```

Эта команда поднимает платформу OpenEgiz (при первом запуске создаёт пароли в `deploy/compose/.env`),
собирает образы рудника, создаёт двойники и запускает сервисы, 3D-сцену и дашборды. Первый запуск
скачивает образы и собирает расширенный API платформы: обычно 10–20 минут в зависимости от сети;
повторный запуск — 2–3 минуты. В конце команда печатает адреса.

Проверка работающего стенда (двойники, телеметрия, сценарии, 3D-страница, история в InfluxDB, Grafana; в конце — перезапуск сервисов переработки и транспорта с проверкой, что бункер, склады и счётчики восстановились):

```bash
make bozshakol-check
```

Остановить (данные остаются) и снова поднять:

```bash
make down
```

```bash
make up
```

## Что открыть в браузере

| Что | Адрес | Вход |
|---|---|---|
| 3D-сцена карьера (панель диспетчера, сценарии «что если», карточки двойников) | http://localhost:8095 | не нужен |
| Grafana → Dashboards → папка **Бозшаколь** (обзор, транспорт, геология, переработка и энергия) | http://localhost:3000 | `admin` / значение `GRAFANA_ADMIN_PASSWORD` из `deploy/compose/.env` (его печатает `make bozshakol`) |
| Grafana → приложение **OpenEgiz** → **Twins** — иерархия двойников `kz.bozshakol` | там же | там же |
| Ditto API: все двойники | http://localhost:8080/api/2/search/things?namespaces=kz.bozshakol | `ditto` / `DITTO_PASSWORD` из `deploy/compose/.env` |

Порты задаются в `deploy/compose/.env` (`GRAFANA_PORT`, `DITTO_PORT`, `BOZSHAKOL_WEB_PORT` и другие);
в таблице — значения по умолчанию.

### 3D-сцена

На странице http://localhost:8095 — **схема рудника** на степи до горизонта: расстояния сжаты в 2 раза, а здания,
склады, отвал и хвостохранилище — в реальном размере (корпус фабрики 320 × 170 м, отвал Ø 800 м; соседи по комплексу
стоят на реальном расстоянии); карьер ≈ 4,4 × 1,1 км, 13 уступов по 15 м с бермами и съездами, глубина — с вертикальным
масштабом ×1,5; подвижная техника — ×1,25 к реальному размеру (экскаватор крупнее самосвала); на дальнем плане над
машиной — цветной значок-стрелка (цвет груза или состояния), вблизи — модель. Вся земля — одна функция высоты:
степь, бермы и стенки уступов, съезды, площадки и дороги; дороги — ленты по этой поверхности, техника стоит на ней
колёсами и наклоняется по уклону, буровые станки — на бермах. Едущие самосвалы держатся своей полосы, очереди к
экскаватору, дробилке, складу глины и стоянка у заправки выстраиваются вдоль подъезда, место в очереди закреплено за
машиной, все сдвиги — плавные (это только картинка — данные двойников не меняются). Двойной клик по объекту — облёт
(Esc — выход); колесо мыши, тачпад и R/F — плавное приближение (≈ 11 % расстояния за щелчок). Места узлов и объектов —
`bozshakol/core/diorama.json`, перенос реальных координат двойников в схему — `bozshakol/web/diorama.js`. Самосвалы
и экскаваторы движутся по данным двойников (шапка груза — по цвету руды: сульфидная зелёная, глинистая рыжая, вскрыша
серая; авария — красный корпус и значок «⛔ авария», резерв — серо-белый).

Реальная местность — кнопка **«Фото местности»**: окно со спутниковым снимком Sentinel-2 (29.06.2024, 10 м/пиксель,
квадрат 6 × 6 км) с подписями «карьер», «дробилка», «фабрики», «отвал», «хвостохранилище» и полной атрибуцией
Copernicus; закрывается крестиком или Esc, сцена от него не зависит. Источники и лицензии — в
[bozshakol/data/terrain/README.md](bozshakol/data/terrain/README.md).

- Кнопки-виды сверху: «Весь рудник», «Карьер», «Дробилка и конвейер», «Фабрики», «Сверху (карта)» —
  вид сверху ортографической камерой как 2D-карта карьера; «Следовать» — камера идёт за выбранным самосвалом.
- Клик по технике или объекту — карточка с живыми признаками двойника. Подписи крупных объектов видны
  всегда, подписи техники — при приближении, наведении или выборе.
- Вверху панели — **«Советы диспетчеру»** (двойник `advisor`, сервис `bz-advisor`): главный совет крупно с причиной и
  ожидаемым эффектом, остальные списком, цвет по приоритету; значок «совет» над объектом в сцене, клик по совету ведёт
  камеру к нему; появление и снятие совета — в журнале событий. Правила — в договоре, раздел 11.
- Слева — панель диспетчера: план/факт обеих фабрик за смену, содержание меди и доля глины в питании,
  ожидание у экскаватора, самосвалы в работе / в очереди / в аварии, погода; журнал событий модели
  (сценарии, остановки, закрытые дороги); сценарии «что если» с кнопками «Включить / Выключить».
- Включённый сценарий показан плашкой «Активные сценарии» сверху и значком на затронутом объекте.
  В истории (InfluxDB, Grafana) сценарии видны по признакам `mine.scenario_<имя>` (1/0) и
  `mine.active_scenarios`; на обзорном дашборде — полоса «Активные сценарии».
- Кнопка **«Фото местности»** сверху — спутниковый снимок реального Бозшаколя с подписями объектов.
- **Качество** в панели: «Высокое» — тени от солнца, ореолы огней, пыль за самосвалами; «Обычное» — быстрее; при первом запуске
  сцена 3 секунды меряет скорость кадров и сама выбирает «Обычное», если кадров меньше 25 в секунду.
- Кнопка **«Как посмотреть»** в правом нижнем углу открывает путеводитель (он же появляется при первом открытии).
- У каждого сценария в панели — строка «что смотреть» и кнопка **«показать»**: камера летит к главному объекту.
- Карьер — уступы с породой, бермами и съездами; вокруг — хвостохранилище, ЛЭП,
  ограждение и мачты освещения (положение части объектов — допущение, см. `bozshakol/data/SOURCES.md`).
- Управление с клавиатуры: **W/A/S/D** и стрелки — движение по карте, **Q/E** — поворот, **R/F** и колесо
  мыши — выше/ниже (ближе/дальше), **Shift** — быстрее; **1–5** — виды, **Home** — «Весь рудник»,
  **Пробел** — следовать за выбранным самосвалом / отпустить, **Esc** — снять выбор, **?** — подсказка.

Сценарии «что если» включаются кнопками в 3D-сцене или записью одного признака, например:

```bash
. deploy/compose/.env && curl -u "ditto:$DITTO_PASSWORD" -X PUT -H 'Content-Type: application/json' -d true "http://localhost:$DITTO_PORT/api/2/things/kz.bozshakol:scenarios/features/crusher_stop/properties/value"
```

Отмена — то же самое с `false`. Полный список сценариев — в [bozshakol/contract/README.md](bozshakol/contract/README.md).

## Как проверить за 5 минут

1. Запустите стенд: `make bozshakol` (первый раз 10–20 минут, повторно 2–3 минуты) и откройте http://localhost:8095.
2. Прочитайте путеводитель «Как посмотреть двойник» (откроется сам) и нажмите «Понятно».
3. Осмотритесь: виды 1–5 («Весь рудник», «Карьер», «Дробилка и конвейер», «Фабрики», «Сверху»), мышь или W/A/S/D.
   Сцена — схема рудника; реальная местность на спутниковом снимке — кнопка «Фото местности».
4. Кликните самосвал: справа — карточка с живыми данными его двойника (груз, скорость, топливо, пункт назначения),
   голубая линия — его маршрут до цели; «Следовать за самосвалом» — камера пойдёт за ним.
5. В панели слева включите сценарий «Остановка дробилки» и нажмите «показать»: у дробилки растёт очередь,
   склад перед фабрикой тает, в подписи склада появляется прогноз «фабрика встанет в …», вверху панели — совет
   диспетчеру с цифрами. Выключите сценарий — очередь рассасывается, совет снимается.
6. Откройте «Дашборды Grafana» (ссылка в панели) → «Бозшаколь — обзор»: подача на фабрики, полоса активных
   сценариев и советы во времени.
7. Кнопка **«Сверка с реальностью»** сверху: таблица «модель / реальность / отклонение» — подача на обе фабрики, содержание
   меди, извлечение, темп меди в концентрате, ожидание у экскаватора, удельная электроэнергия; зелёный — в пределах ±10 %,
   жёлтый — больше; источник каждой реальной цифры — в подсказке строки. Подача на фабрики совпадает по построению
   (план модели взят из того же отчёта) — это калибровка, а не независимая проверка. История — Grafana → «Бозшаколь — сверка с реальностью».
8. Проверка стенда одной командой: `make bozshakol-check`.

В первый модельный час после старта (≈ 6 минут реального времени) советник пишет «рудник разгоняется»: оценка
привоза руды за час появляется, когда накопится час данных; в сверке с реальностью в это время пометка «модель разгоняется».
Величина, которую модули не публикуют, в сверке показана как «нет данных» (сейчас — удельная электроэнергия).

## Как устроен репозиторий

| Путь | Содержимое |
|---|---|
| `bozshakol/` | Всё наше. `contract/README.md` — договор команды: имена и иерархия двойников, протокол телеметрии, счётчики, сценарии, владельцы папок |
| `bozshakol/core/` | Координатор: создание двойников (`bz-setup`), модельное время, погода, итоговые показатели (`bz-core`), `geometry.json`, общая библиотека `bzlib/` |
| `bozshakol/modules/haulage/`, `geology/`, `processing/` | Модули: транспорт и диспетчеризация, геология и качество руды, переработка и энергия — по сервису, `twins.json` и README на модуль |
| `bozshakol/web/` | 3D-сцена (three.js локально, nginx), слои модулей в `web/layers/` |
| `bozshakol/grafana/` | Дашборды Grafana |
| `bozshakol/data/SOURCES.md` | Источники цифр и допущения |
| `bozshakol/data/terrain/` | Рельеф Copernicus DEM и снимок Sentinel-2 вокруг карьера (готовые файлы + скрипт воспроизведения, лицензии) |
| `bozshakol/check.sh` | Проверка работающего стенда |
| `SUBMISSION.md` | Описание решения |
| `examples/mine/` | Пример рудника из шаблона платформы; в решении не используется |
| `OPENEGIZ.md`, `OPENEGIZ.ru.md` | Документация платформы OpenEgiz v1.0.4: требования, Windows/WSL2, устранение неполадок |

Справка о платформе (установка Docker, Windows/WSL2, `make up`, `make smoke`, `make clean`) —
в [OPENEGIZ.ru.md](OPENEGIZ.ru.md) / [OPENEGIZ.md](OPENEGIZ.md).
